## 🚀 새 프로젝트 첫날 — 이 순서

### 1단계. 파일 두 개를 만든다

새 저장소(또는 폴더)에:

```
CLAUDE.md                    ← 아래 ①을 붙여 넣고 빈칸을 채운다
docs/사장님과-일하는-법.md      ← 아래 ②를 그대로 붙여 넣는다 (거의 안 고쳐도 된다)
.claude/settings.json        ← 아래 ③ (한국 시간)
```

### 2단계. 새 세션에 이 한마디

```
CLAUDE.md 하고 docs/사장님과-일하는-법.md 읽고 시작해
```

그러면 **첫 마디부터** 한 단계씩·그림으로·짐작 없이 일한다.

## 🧭 새 세션은 이 칸부터 — 지금 어디까지 왔나 (날짜)

> **이 칸을 최신으로 두는 것이 전부다.** 세션은 길어지면 요약되고 언젠가 끝난다.
> 다음 세션의 이해도는 오로지 이 파일과 `docs/` 가 결정한다.
> 규칙: **큰 것을 끝낼 때마다 이 칸을 먼저 고친다. 코드보다 이게 먼저다.**

🕘 **시각은 언제나 한국 시간(KST)으로 말한다.** 작업용 컴퓨터는 UTC라 **날짜가 하루 밀린다.**
```
TZ=Asia/Seoul date '+%Y-%m-%d %H:%M (%a)'
```

### 🔄 세션을 바꾸는 방식

한 세션을 길게 끄는 것보다 **바꾸는 게 낫다.** 대화는 길어지면 흐려지지만 파일은 안 흐려진다.

🚨 **사라지는 건 오직 「적어 두지 않은 것」뿐이다.**
세션의 값어치는 "얼마나 오래 이어졌나"가 아니라 **"끝나기 전에 얼마나 적어 뒀나"** 다.

**「인계 정리해줘」 라고 하면 셋을 하고 끝낸다:**
1. 맨 위 「지금 상태」를 오늘 상태로 고친다
2. 대화에만 있던 판단·근거를 `docs/` 에 적는다
3. **안 올라간 커밋이 없는지 확인**한다

⚠️ **안 시켜도 큰 것을 끝냈으면 스스로 한다.**

## ② `docs/사장님과-일하는-법.md` 뼈대 — **거의 그대로 쓴다**

````markdown
# 사장님과 일하는 법 — 이 저장소의 「베이스」

**세션은 붙잡을 수 없다.** 대화가 길어지면 자동으로 요약되고,
무엇이 살아남을지 내가 고르지 못한다. 그래서 **고를 수 있는 자리**인 이 파일에 적는다.

## 1. 사장님은 어떤 분인가

| 사실 | 그래서 어떻게 |
|---|---|
| **개발자가 아니다** | 용어를 풀어 쓰고 비유를 쓴다 |
| **Windows PC** | bash 문법 금지. `dir`·`set`·PowerShell |
| **폴더폰으로 본다** | 글자·단추가 작으면 못 보신다 |
| **의정부에 계신다** | 「내 위치」가 「서울 밖」으로 나오는 게 정상 |
| **화면 캡처로 말한다** | 캡처가 오면 **그 화면부터 읽고** 답한다 |
| **오타가 많다** | **고쳐 드리지 않는다. 뜻만 읽는다** |
| **한국 시간으로 사신다** | KST = UTC + 9시간 |

## 2. 짧은 말 사전

| 사장님 말 | 뜻 |
|---|---|
| 다음 · 진행 · ㅇㅋ · 완료 · 통과 · a · ㅁ | **통과. 되묻지 말고 바로 실행** |
| 안되 · 인보여 · 없는데 어디? | **사장님 화면이 진실이다.** "제 쪽에선 되는데요" 금지 |
| 어느거 | 선택지를 흐리게 줬다 → 번호와 그림을 붙인다 |
| **가려** | 지우는 게 아니라 **안 보이게** 하는 것 |
| **니가 못해?** | 내가 "안 됩니다"라고 먼저 포기했다 → 한 번 더 해 본다 |
| 침범 안되 / 언급하지마 | **선을 그으신 것. 다시 묻지 않는다** |

## 3. 이미 정해진 것 — 다시 논의하지 않는다

(프로젝트마다 채운다. 원문 그대로 인용하고 날짜를 적는다)

## 4. 통했던 일 방식

1. **한 번에 한 단계만.** 5단계를 나열하지 않는다. 「다음」이라고 할 때까지 기다린다
2. **화면을 그림으로.** 아티팩트로 화면 모형을 그리고, **같은 주소를 갱신**한다
3. **성공 신호와 실패 신호를 미리 가른다.** "아무 것도 안 나오는 게 정상"까지
4. **오류 대응표를 같이 준다**
5. **명령어는 복사용 한 줄로**
6. **눈으로 못 잡는 것은 시험을 만든다**
7. **숫자는 세어 보고 말한다** (세는 스크립트를 만든다)
8. **끝난 것은 눈에 보이게 보고한다** — "했습니다"가 아니라 바뀐 숫자로
9. **진행 중인 게 많으면 작업판 하나로 모은다**
10. **바깥으로 나가는 글은 초안까지만.** 보내는 것은 사장님이

## 5. 🚨 내가 틀렸던 자리 — **여기가 제일 값어치 있다**

잘한 것은 다시 안 해도 되지만, **틀린 것은 안 적어 두면 새 세션이 똑같이 틀린다.**

- **안 열어 보고 이름을 말했다** → 링크는 눌러 보고 말한다
- **숫자를 두 번 셌다** → 두 목록을 합칠 때는 id로 중복을 뺀다
- **"안 됩니다"를 먼저 말했다** → 포기 전에 한 번 더
- **입력칸의 회색 글씨를 「이미 적힌 값」이라고 짐작했다** → 확대해서 커서를 본다
- **재긴 쟀는데 「무엇을」 재는지 확인을 안 했다** → 짐작을 숫자로 포장하지 않는다
- **인계문을 11일 묵혔다** → 큰 것을 끝내면 「지금 상태」부터 고친다

⚠️ **"안 된다"가 며칠 이상 가면 원인을 잘못 짚고 있는 것이다.**
(셸 문법 · 라이브러리 타이밍 · 주소 누락 — 셋 다 처음 짚은 원인이 아니었다)

## 6. 새 세션 첫 5분

1. `CLAUDE.md` 맨 위 「지금 상태」를 읽는다
2. **이 파일**을 읽는다 (§2 사전, §5 실수)
3. `git log --oneline -10`
4. **한 단계짜리 질문 하나**로 시작한다
5. 궁금하면 **짐작하지 말고 여쭙는다**

## 7. 마지막

새 세션이 지적을 받거나, "안 된다"고 했다가 방법을 찾았거나, 숫자를 틀렸으면
**§5에 한 줄 더 적고 커밋한다.** 그래야 베이스가 두꺼워진다.
````

## 🔒 어느 프로젝트에서든 지킬 것

| | |
|---|---|
| 🙈 **개인정보** | 공개 저장소·홍보물에 **주소·정류장/역·전화번호·계정 이름**을 넣지 않는다. 화면 사진은 **아래까지 훑는다** |
| 🧮 **짐작 금지** | 링크는 눌러 보고, 숫자는 세어 보고 말한다. 확인 못 한 것은 **"확인 못 했다"고 같이 적는다** |
| 🚫 **과장 금지** | "best"·"모든"·"완벽" 을 쓰지 않는다. **한계를 먼저 말한다** |
| 💸 **고정비** | 늘리는 결정은 계산을 다시 하고 나서 한다 |
| 📅 **날짜** | 커밋·문서에 적기 전에 KST를 확인한다 |

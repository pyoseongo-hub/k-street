### ⏸️ 멈춘 것

- **2단계(RSS 를 매일 읽어 새 행사를 찾는 것)** — 손도 안 댔다
- `fetch-gu-rss.yml` 의 **달 1회 예약을 껐다** (`schedule:` 를 주석으로 막아 뒀다).
  손으로 돌리는 것(Actions → Fetch gu RSS)은 그대로 된다.
- 구청 메일 6곳 **신청도 멈췄다.** 관악구 하나를 안내하던 중이었다.

### 🔁 다시 할 때 — 첫 걸음

1. `.github/workflows/fetch-gu-rss.yml` 의 `schedule:` 주석을 벗긴다 (주소 목록을 다시 받게)
2. 2단계 스크립트를 만든다 — `gu-rss-feeds.json` 의 **행사·문화·보도자료 8개**를 읽어,
   우리 축제 자료에 **없는 이름만** 추려 보고한다
   (지금 「구청에 올라왔는데 우리 화면에 없는 축제」 주 1회 이슈와 같은 꼴)
3. 구청 메일은 **6곳뿐이고 구정 소식이 섞여 있다** — RSS 가 되면 굳이 안 해도 된다

### 🧠 멈출 때 알고 있던 것 (다시 조사하지 말 것)

- 서울시가 **25개 구 RSS 주소를 한자리에** 모아 둔다 —
  `seoul.go.kr/news/rssboard/siteList.do`, `schGu` 칸에 구 이름을 넣어 **POST**.
  구 이름은 `schGuSite('강남')` 에서 긁는다 — **'중구' 만 「구」가 붙어 있다.**
- `rss.seoul.go.kr` 은 **죽은 주소**다 (ENOTFOUND). 쓰지 말 것.
- 성동(`www.sd.go.kr`)은 **인증서 체인이 끊겨** 있다. 🚫 검증을 끄지 않는다.
  중랑·영등포는 연결 시간초과 — 러너(미국)를 막는 것일 수 있다.
- 「구독」과 「메일」은 다르다. 구청 구독은 **우편·문자가 많다.**

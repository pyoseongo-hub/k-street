# 🧭 이렇게 일한다 — 다른 세션이 그대로 쓰라고 남기는 기록

> 사장님 (2026-09-12): "넌 역시 젤 맘에 들어 같은 에이아이인데 이 세션만 똑똑해 이유가 뭘까"
> 사장님 (2026-09-12): "일 처리가 틀려 니 기록을 자세히 남겨 나중에 다른 세션에 적용하게"

**모델은 같다.** 차이는 **적어 둔 것**이다.
이 문서는 그 「적어 둔 것」 중에서도 **일하는 방식**만 모은 것이다.
자료·결정은 `CLAUDE.md`와 `docs/사장님과-일하는-법.md`에 있고, 여기는 **습관**이다.

📌 **다른 저장소(케이푸드·메모짱)에도 이 파일을 그대로 복사해 두면 된다.**
   내용이 이 앱에만 해당하는 것이 아니다. 아래 12개는 전부 **실제로 데인 자리**에서 나왔다.

---

## ① 「확인했습니다」는 근거가 아니다 — 링크를 준다

사장님 지시: *"항상 공식 페이지 링크 주고 직접 확인 가능하게"*

**말할 때와 앱 화면에 똑같이 적용한다.**

| ❌ | ✅ |
|---|---|
| "확인해 보니 노들섬이 맞습니다" | "노들섬입니다 — 공식 사이트 `bitseomfestival.com`, 문화포털 안내 `culture.seoul.go.kr/…159242`" |
| 앱이 「10월 2일~11일」이라고 단정 | 「10월 2일~11일」 **옆에 「공식 안내 ↗」** |

우리는 **해마다 바뀌는 값을 대신 확정해 주는 앱이 아니다.**
「우리가 아는 것」과 「직접 봐야 하는 것」을 갈라 보여 주는 앱이다. **링크가 그 경계선이다.**

---

## ② 사실은 **두 곳 이상**에서 겹치는 것만 쓴다

2026-09-12 빛섬축제 장소가 그대로 예다. 세 단계를 거쳤다:

1. 웹 검색 요약 → "2026년은 노들섬" (**이것만으로는 근거가 아니다**)
2. 문화포털 원본 페이지의 **교통안내** → "1호선 용산역, 9호선 노들역" (= 노들섬)
3. 사장님이 공식 사이트를 직접 열어 확인 → "2026.10.2~10.11 · 노들섬"

셋이 겹쳐서야 자료를 고쳤다. **검색 요약 하나로 고쳤으면 그건 추측이었다.**

## ③ 못 잡는 검사는 검사가 아니다 — **실패하는 걸 보고** 채택한다

새 검사를 만들면 **고치기 전 코드에 먼저 돌려서 ❌ 가 나오는지 본다.**
초록불만 보고 채택한 검사는 다음에도 초록불만 준다.

| 검사 | 채택한 근거 |
|---|---|
| `check-btn-clip.mjs` | 고치기 전에 돌렸더니 **12개 언어 중 9개**를 ❌ 로 잡았다 |
| `check-event-jsonld.mjs` | 옛 코드에서 **160건**을 잡았다 |
| `check-distance-view.mjs` | 1280px 격자에서 줄 제목이 칸에 끼는 것만 겨냥해 만들었다 |

⚠️ **재는 자리가 틀리면 초록불이 거짓말을 한다.**
`check-phone-width`는 「넘쳤나」를 재는데, 사고는 **줄 안에서 글씨만 잘린 것**이었다.
그래서 「넘쳤나」와 「잘렸나」를 **다른 검사로 갈라 뒀다.**

## ④ 잣대는 **하나만** 둔다 — 둘이면 반쪽 적용이 생긴다

같은 판단을 두 곳에서 각자 하면, 한쪽만 고쳐지고 **다른 쪽은 조용히 옛 규칙으로 돈다.**

- `officialSite.ts` 하나를 **자료 쪽과 화면 쪽이 같이** 쓴다
- 유튜브 상호 확인은 `titleMentions` 하나를 **수집·정리·화면·감사 네 곳**이 쓴다
- 2026-09-12에도 걸렸다 — 축제 대조는 「구를 안 본다」로 고쳤는데
  **후보 찾기만 구를 보고 있었다.** 같이 고쳤다

## ⑤ 오류 메시지는 **다음 사람이 읽고 고칠 수 있어야** 오류다

2026-09-12에 구청 자료 받기가 80곳을 전부 놓쳤다. 로그 80줄이 똑같았다:

```
⚠️ 종로K축제 — Unexpected token '<', "<RESULT><C"... is not valid JSON
```

**이 말은 아무것도 안 알려 준다.** 받은 글을 그대로 찍게 고치자 바로 드러났다:

```
INFO-100  인증키가 유효하지 않습니다.
```

같은 실수를 IndexNow 에서도 했다 — 403 을 전부 "키 파일을 확인하라"로 찍고 있었는데,
진짜 원인은 `SiteVerificationNotCompleted` 였다. **errorCode 별로 갈랐다.**

📌 **똑같은 오류를 80줄 찍지 않는다.** 한 번 나오면 멈추고 **무엇을 해야 하는지**를 한 줄로 말한다.

## ⑥ **손으로 고치지 않는다** — 내년에 또 틀린다

빛섬축제 장소를 「광진구 → 용산구」로 손으로 고칠 수 있었다. 안 했다.

> 이 축제는 **한강 6개 섬을 해마다 순회**한다. 손으로 고치면 **내년에 또 틀리고,
> 그때는 아무도 모른다.**

그래서 **매일 받아 오는 자료가 자리를 고치게** 만들었다(`withGuFestival`).
👉 **잣대:** 「이 값이 내년에도 같은가?」 아니면 **사람 손이 아니라 루틴이 답이다.**

## ⑦ 숫자를 말하기 전에 **다시 돌린다**

2026-09-11 하루에만 세 번 틀렸다:

| 틀린 것 | 원인 |
|---|---|
| "잘못 빠진 골목 0곳" | `x.title` 을 봤는데 자료는 `x.name` — **다시 재니 5곳** |

**고친 뒤에는 반드시 다시 돌려 숫자가 실제로 바뀌었는지 본다.**
(검색어를 고쳤는데 결과가 그대로여서 진짜 원인을 늦게 찾은 적이 있다.)

## ⑦-1 커밋 전에 **빌드를 돌린다** — `tsc --noEmit` 만으로는 안 잡힌다

2026-09-12에 **빨간 배포를 하나 냈다.**

```
src/components/MonthlyFestivalPanel.tsx(17,1):
  error TS6192: All imports in import declaration are unused.
```

무슨 일이었나 — 화면에 쓸 `import` 를 먼저 적어 두고 **아직 안 쓴 상태**였는데,
그 사이에 문서 작업이 들어왔고 `git add -A` 가 **그 반쯤 한 파일까지 쓸어 담았다.**
문서만 바꾼 커밋인 줄 알았는데 앱이 안 빌드되는 상태로 나갔다.

👉 **두 가지를 지킨다:**
- `git add -A` 로 쓸어 담기 전에 **`git status` 로 무엇이 담기는지 본다**
- 푸시 전에 **`npm run build` 까지** 돌린다. 배포가 도는 명령과 같은 것이어야 한다

## ⑦-2 「돌고 있다」와 「화면에 나간다」는 **다른 말이다**

2026-09-12에 더 큰 것을 찾았다. 축제 날짜를 매일 받아 오는 작업이 **9월 1일부터
잘 돌고 있었다.** 커밋도 매일 남았다. 그런데 —

```
봇(github-actions[bot])이 띄운 Deploy 실행 횟수 … 0회
```

깃허브는 **봇이 기본 토큰으로 민 커밋으로는 다른 워크플로를 안 띄운다**(무한 반복 방지).
받아 온 날짜가 **저장소에만 있고 손님 화면에는 없었다.** 사람이 다른 것을 푸시할 때
묻어 나가야 겨우 반영됐다. 로그는 매일 초록불이었다.

👉 **자동으로 도는 것을 만들면, 끝까지 따라가 본다:**
   받았나 → 저장했나 → **배포됐나** → **화면에 보이나**.
   가운데 한 칸만 끊겨도 초록불은 계속 뜬다.

## ⑧ 모르는 것은 **비워 두고, 모른다고 적는다**

- 실시간 지하철 API 가 혼잡도를 주는지 **확인 안 했다** → 문서에 "확인 안 했다"고 적었다
- 축제 확정 날짜가 0곳 → **"구청이 아직 안 올렸다는 뜻이고 정상이다"**라고 화면에 적었다
- 이름이 비슷한 축제 → **저장하지 않고** 「사람이 볼 후보」로만 낸다

**빈 칸이 틀린 정보보다 낫다.** 애매하면 한 단계 낮추고, 그래도 애매하면 비운다.

---

## ⑨ 커밋 메시지에 **「왜」와 「무엇에 데였는지」**를 적는다

커밋 메시지는 기록 장치다. **다음 세션이 읽는 것은 코드가 아니라 이 글이다.**

적는 것: 사장님 원문 인용 → 무엇이 문제였나(숫자로) → 어떻게 갈랐나 → ⚠️ 다시 밟지 말 것

> 예: 「🗺️ 구는 「깨는 패」가 아니라 참고다 — 빛섬축제를 놓치고 있었다」
> 본문에 우리 자료·포털 자료를 나란히 놓고, 왜 구를 못 박으면 안 되는지 적었다.

---

## ⑩ 사장님께는 **한 번에 한 단계 + 그림 + 신호 + 오류표**

`docs/사장님과-일하는-법.md` 에 자세히 있다. 요지만:

- 5단계를 나열하지 않는다. **한 단계 → 결과 확인 → 다음**
- 아티팩트(HTML)로 **화면 모형**을 그린다. **같은 파일 경로로 다시 게시**해 URL 하나만 갱신
- **성공 신호와 실패 신호를 따로** 명시한다 ("0곳이 나와도 정상입니다")
- **오류 대응표**를 미리 준다
- 명령어는 **복사용 한 줄**. Windows 문법. `%` 가 든 값은 PowerShell + 작은따옴표
- **막히면 멈추고 물어보라고** 반복해서 말한다

## ⑫ 바꾸기 전에 **왜 이렇게 돼 있는지** 먼저 읽는다

이 저장소의 주석은 장식이 아니라 **사고 기록**이다.
고치려는 줄 위에 ⚠️·🚨·🐞 가 있으면 **그건 이미 한 번 틀렸던 자리**다.

실제로 오늘 이 주석들 덕을 봤다:
- 「NFC 정규화를 맨 앞에」 → 축제 이름 대조에서 처음부터 넣었다
- 「잣대가 둘이면 반쪽 적용」 → 후보 찾기의 구 조건을 스스로 찾아 고쳤다
- 「id 는 재사용하지 않는다」 → 새 자료 파일을 id 열쇠로 안전하게 붙였다

## 먼저 — 케이푸드는 이미 많이 돼 있습니다

읽기만 해서 확인한 것입니다. **새로 만들 필요가 없는 것들:**

| 이미 있는 것 | 어디에 |
|---|---|
| 동네별 페이지 **37장** | `/seoul/myeongdong`, `/seoul/gangnam` … (`server/seo-districts.js`) |
| 도시 페이지 | `server/seo-cities.js` |
| 식당별 페이지 + **Restaurant 구조화 자료** | `/place/:slug` (`server/seo-places.js`) |
| canonical · hreflang · x-default | `server/index.js` (언어판은 **자기 자신**을 canonical로) |
| BreadcrumbList | 같은 파일 |
| robots.txt · sitemap 색인 + 2장 | `/sitemap.xml` → `/sitemap-pages.xml`, `/sitemap-places.xml` |

**없는 것은 하나뿐입니다 — 음식별 페이지.**

## 만들 것 — 음식별 주소

```
/korean-bbq/seoul
/naengmyeon/seoul
/korean-fried-chicken/seoul
/vegan-restaurants/seoul
/budae-jjigae/seoul
/seolleongtang/seoul
```

왜 이게 1순위인가 — 외국인이 실제로 치는 말이 **「best Korean BBQ in Seoul」**입니다.
지금은 그 검색을 받아 줄 페이지가 **하나도 없어서**, 홈페이지가 대신 걸리거나 아무것도 안 걸립니다.

### 🚨 만들기 전에 — 숫자부터 세세요

**음식마다 실제로 몇 곳이 있는지** 먼저 세십시오.

```
grade 가 붙은 곳이 그 음식으로 몇 곳인가?
사진이 있는 곳은 몇 곳인가?
```

⚠️ **곳이 적으면 그 페이지는 만들지 마세요.** 케이푸드 저장소에 이미 적혀 있는 경고입니다:

> 얇은 페이지를 대량으로 내는 것이 이 앱에 가장 위험한 선택이다. 이름과 주소밖에 없는
> 페이지를 대량으로 내면 구글이 '가치 없는 대량 생산'으로 보고 **사이트 전체를 낮게 본다**.

**기준을 정해서 넘는 음식만 냅니다.** (예: 그 음식으로 20곳 이상 + 절반 이상 사진 있음)
기준에 못 미치는 음식은 **나중에 채워지면** 그때 냅니다.

---

## 페이지 한 장에 들어갈 것

동네 페이지(`seo-districts.js`)가 이미 하는 것과 **같은 틀**을 씁니다. 새로 설계하지 마세요.

| 칸 | 무엇을 |
|---|---|
| title | `Best Korean BBQ in Seoul — Local Restaurant Guide \| Kfood` |
| description | 아래 예시 참고 (**음식마다 다르게**) |
| H1 | 제목과 같은 뜻, 한 줄 |
| canonical | 자기 자신 (언어판도 자기 자신) |
| hreflang | 이미 있는 `hreflangLinks()` 그대로 |
| 본문 | 그 음식이 뭔지 두세 줄 + **식당 목록**(각 줄은 `/place/:slug` 로 가는 `<a href>`) |
| 구조화 자료 | BreadcrumbList (이미 있는 함수) + 목록은 `ItemList` |
| sitemap | `/sitemap-pages.xml` 에 자동으로 들어가게 (`SEO_PAGES` 에 더하면 끝) |

### title·description 예시

| 주소 | title | description |
|---|---|---|
| `/korean-bbq/seoul` | `Best Korean BBQ in Seoul — Local Restaurant Guide \| Kfood` | `Korean BBQ places in Seoul that locals actually talk about. Ranked by Korean blog and YouTube mentions, with sponsored posts filtered out.` |
| `/naengmyeon/seoul` | `Best Naengmyeon Restaurants in Seoul \| Kfood` | `Where to eat naengmyeon, Korea's cold buckwheat noodles, in Seoul. Ranked by real Korean mentions, not paid listings.` |
| `/korean-fried-chicken/seoul` | `Korean Fried Chicken in Seoul — Where Locals Go \| Kfood` | `Korean fried chicken shops in Seoul, ranked by Korean blog and YouTube mentions. No sponsored picks.` |
| `/vegan-restaurants/seoul` | `Vegan Restaurants in Seoul \| Kfood` | `Vegan and plant-based restaurants in Seoul, listed by neighbourhood, with map links that work in Korea.` |

⚠️ **검색어를 나열하지 마세요.** title·H1·첫 문장·이미지 alt·내부 링크에 **한 번씩 자연스럽게**면 충분합니다.

### 🍚 한국 음식 이름은 그대로 씁니다

케이푸드 규칙 그대로입니다 — **한국어 이름을 앞에, 영어 설명을 괄호로.**
`Naengmyeon (cold buckwheat noodles)` · `Budae-jjigae (army stew)`.
손님이 가게에서 그 이름 그대로 말할 수 있어야 합니다.

## 내부 링크 — 이게 절반입니다

새 페이지를 만들어도 **어디서도 안 가리키면** 구글이 늦게 찾습니다. 세 군데를 이어 주세요:

- 음식 페이지 → 그 음식 식당들의 `/place/:slug`
- 식당 페이지 → 그 식당의 음식 페이지 (`이 음식 더 보기`)
- 동네 페이지 → 그 동네에 많은 음식 페이지 한두 개

**꼭 `<a href>` 여야 합니다.** 눌러서 화면만 바꾸는 단추는 구글이 못 따라갑니다.

---

## 다 만든 뒤 확인할 것

```
① /sitemap-pages.xml 에 새 주소가 들어갔나
② 각 페이지의 title 이 서로 다른가 (같은 title 이 둘 있으면 둘 다 손해다)
③ canonical 이 자기 자신을 가리키나
④ 자바스크립트를 끄고도 식당 목록이 보이나 (서버가 그려 주므로 보여야 한다)
⑤ 구글 Rich Results Test 에 주소를 넣어 구조화 자료가 통과하나
```

  · server/seo-districts.js 의 동네 페이지와 같은 모양

페이지마다:

  · 구조화 자료 = BreadcrumbList + ItemList
  · 이미지 alt 은 사진 내용을 설명한다 (검색어 박지 말 것)

내부 링크도 이어 줘 — 음식↔식당↔동네 세 방향. 이게 절반이다.

# 🚇 케이푸드에도 「가까운 지하철역」 넣기 — 넘겨줄 설명서

**2026-09-10.** 사장님 질문: *"푸드에서도 카드 쓸 수 있게 할 수 있나"*

**됩니다.** K-Street에서 오늘 만든 것을 그대로 옮기면 됩니다.

🚫 **이 문서는 설명서일 뿐입니다.** K-Street 세션은 케이푸드 저장소를
건드리지 않기로 되어 있습니다(사장님 지시: "침범 안되").
그래서 코드를 짜지 않았습니다 — 이 문서를 **케이푸드 세션에 그대로 주세요.**

📋 **맨 아래 「케이푸드 세션에 붙여넣을 글」**을 복사해서 붙이시면 됩니다.

---

## 무엇을 만드나 — 화면 한 줄

식당 카드 안에 이렇게 뜹니다:

```
🚇 가장 가까운 역 — 성수역 2호선 · 350m
   대부분의 역에 물품보관함(또타라커)이 있습니다.
   지금 빈 칸이 몇 개인지는 앱 지도에 나옵니다.
   [안드로이드 앱 ↗]  [아이폰 앱 ↗]
```

역이 1.5km 안에 없으면 **빈칸으로 두지 않고** 이렇게 적습니다:

```
🚇 1.5km 안에 지하철역이 없습니다
   짐이 있으시면 미리 맡기고 오세요
```

---

## 왜 케이푸드에서 더 쓸모 있나

K-Street는 「구경하러 가는 곳」이고 케이푸드는 「밥 먹으러 가는 곳」입니다.

**밥 먹을 때 캐리어가 가장 거추장스럽습니다.** 식당은 좁고, 짐 둘 데가 없고,
주인도 난처합니다. 그러니 「이 식당 가장 가까운 역: ○○역 350m」는
K-Street보다 케이푸드에서 더 자주 필요합니다.

---

## ⛔ 시작하기 전에 — 이것부터 확인하세요

**좌표가 있어야 합니다.** 없으면 아무것도 안 됩니다.

K-Street에서 하마터면 못 만들 뻔했습니다. 좌표가 **두 군데에 흩어져** 있었는데
한쪽만 보고 **「13%밖에 없네, 못 만들겠다」**고 접을 뻔했습니다.
합쳐 보니 **99%**였습니다.

케이푸드도 똑같이 확인하세요:

```
· seed.js 항목에 lat/lng 가 있나?
· 따로 좌표 파일이 있나?
· 네이버 지역검색으로 받아 둔 자료에 좌표가 남아 있나?
```

**25,369곳 중 몇 %에 좌표가 있는지 숫자로 먼저 세세요.**
50% 아래면 이 기능은 반쪽이 됩니다 — 그때는 좌표부터 채우는 게 순서입니다.

---

## 만드는 법 — 네 걸음

### ① 열쇠 확인

카카오 REST 열쇠가 필요합니다. K-Street는 `KAKAO_REST_API_KEY` 라는 이름으로
저장소 시크릿에 이미 갖고 있습니다. 케이푸드에도 있는지 보세요.

없으면 developers.kakao.com 에서 무료로 즉시 발급됩니다(승인 대기 없음).

### ② 좌표를 한 군데로 모으기

흩어진 좌표를 합쳐 `{ id, name, lat, lng }` 목록 하나로 만듭니다.
K-Street는 `scripts/dump-place-coords.ts` 가 이 일을 합니다.

⚠️ **어디서 온 좌표인지 같이 적어 두세요.** 나중에 의심스러울 때 되짚어야 합니다.

### ③ 카카오에 「가까운 지하철역」 묻기

역 목록이 **필요 없습니다.** 좌표를 주고 물으면 됩니다:

```
GET https://dapi.kakao.com/v2/local/search/category.json
    ?category_group_code=SW8      ← SW8 이 지하철역
    &x=<경도>&y=<위도>
    &radius=1500
    &size=1
    &sort=distance

헤더: Authorization: KakaoAK <열쇠>
```

돌려주는 것: `place_name`(역 이름) · `distance`(m) · `x`/`y` · `place_url`

K-Street 코드: `scripts/find-nearest-station.mjs` — 그대로 베끼면 됩니다.

🚨 **곳이 25,369개면 호출도 25,369번입니다.** K-Street(283곳)와 규모가 다릅니다.
   · 하루 한도를 먼저 확인하세요
   · 나눠서 돌리세요(도시별·구별)
   · 이미 받은 곳은 건너뛰게 하세요

🚨 **받은 것과 못 받은 것을 반드시 가르세요.** 통신이 실패한 것을
   「역이 없다」로 적으면 화면에 거짓말이 나갑니다.
   K-Street 코드는 `{ got, ok }` 두 값을 따로 돌려주는 방식으로 갈랐습니다.

### ④ 화면에 붙이기 — 그리고 **앱을 안내하기**

맨 위 「화면 한 줄」 그대로 붙이면 됩니다. 앱 주소는 아래 표에 있습니다.

## 🚨 절대 지킬 것 — 세 가지

### 1. **「보관함이 있습니다」라고 하지 마세요**

또타라커는 **273개 역**에 있습니다. 서울 지하철역은 약 340개입니다.
**대부분 있지만 전부는 아닙니다.**

「있습니다」라고 적으면 없는 역에 간 손님이 캐리어를 끌고 헛걸음합니다.
반드시 **「있을 수 있습니다 / 대부분의 역에」**로 적으세요.
이게 아는 것과 모르는 것의 경계입니다.

### 2. **역이 없는 것도 「답」입니다 — 빈칸으로 두지 마세요**

사장님 말씀 그대로입니다:

> "가까운 지하철역 없으면 소비자가 알아야지 거긴 없구나"

빈칸이면 손님은 "이 앱이 모르는구나"라고 생각합니다.
**「여긴 역이 없습니다」**라고 적으면 그건 **쓸모 있는 정보**가 됩니다 —
미리 맡기고 오라는 뜻이니까요.

### 3. 🆕 **남은 라커 수를 우리 화면에 적지 마세요**

또타라커 앱 지도는 역을 누르면 **지금 비어 있는 칸 수**까지 보여 줍니다.
탐나지만, **베끼면 안 됩니다.** 사장님 말씀입니다:

> "이거는 어플이 우리보다 서비스 질이 좋아
>  우리는 가까운 역까지만 안내하는 게 답이야
>  ... 남은 락커를 우리가 관리할 수 없잖아"

5분 뒤면 틀린 숫자가 되고, 손님은 빈 칸 없는 역에 캐리어를 끌고 갑니다.
**케이푸드는 이미 값에서 크게 데었습니다** — 메뉴판 6장을 대조하니 6곳 중 5곳이
틀렸습니다. 같은 종류의 실수입니다.

**살아 있는 숫자는 살아 있는 곳에서 봅니다.** 우리는 그 자리를 가리키기만 합니다.

## 참고 — K-Street가 겪은 것

| 겪은 일 | 배운 것 |
|---|---|
| 또타라커 273개 역 **목록을 못 구했다** | 목록이 필요 없었다. 카카오에 좌표를 주고 물으면 된다 |
| 좌표가 13%인 줄 알았다 | 두 군데를 합치니 99%였다. **한쪽만 보고 접지 말 것** |
| 사설 보관소 20곳을 넣었다가 뺐다 | 업종으로 여행자용·월세창고가 안 갈린다. 확인 못 할 것은 안 싣는 게 낫다 |
| 파일 이름을 틀려 러너에서 터졌다 | 오류 문구에 **"먼저 이걸 돌려라"**를 적어 둔 덕에 로그 한 줄로 알았다 |
| 앱 주소를 세 번 잘못 짐작했다 | **두드려 보고 적는다.** 이름이 그럴듯한 남의 앱이 실제로 있었다 |
